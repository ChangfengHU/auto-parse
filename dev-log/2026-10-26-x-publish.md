## Change

Add x_publish to the existing engine, managed node catalog and workbench. The formal Supabase workflow has prepare, conditional submit and screenshot nodes. Existing workflow definitions are unchanged. Do not create a standalone publisher, migrate cookies or restart browsers.

The authenticated runtime verifies username, exact text, single composer and no media/thread. Publishing requires same-session preparation proof and directPublish=true. A disk-synced atomic account/content reservation precedes one click; receipt checks native CreateTweet endpoint, account, exact text (including declared t.co expansion) and string post ID. Unknown outcomes fail closed. x_publication_status reads durable state after disconnect/restart without publishing. Preserve .data/x-publications.

Workbench supports multiline X text and links to saved native post receipts. Initial scope is single text posts, Unicode/newlines/hashtags/links; no media, replies, quotes, threads or schedules. UI/browser changes can require maintenance; no official developer API is used.
