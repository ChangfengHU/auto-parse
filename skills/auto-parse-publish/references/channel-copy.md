# 同一作品，多渠道表达

这是本插件的编辑策略起点，不是平台算法结论或“爆款保证”。优先用户明确文案、账号历史语气和本次发布目的；无需为日常写作额外询问。正文事实只能来自作品、上下文和已核实资料。标题可以制造悬念，不能凭空增加剧情、承诺或经历。

## 内容分层

- 原作品：视频本体、真实主题、默认标题正文、AI来源分类。
- 渠道方案：workId + platform + accountId（已知时）分别保存标题、description、topics和可选封面。账号不同也可不同；用户明确只要写作时先交付文案，不擅自保存或发布。
- 实际投递：当次工具解析后的publicationInput与真实回执。不用新方案倒推旧投递；方案封面不代表平台已应用。

先get_channel_content，检查source、revision和history；只有确需改写才做新方案。用户已经指定确切文案且合规可用时保留；超出工具限制时先给语义完整的短版，不静默截断或捏造段落。明确要求原文不动而工具不接受时说明冲突。

## 同一虚构短片的差异示例（不是本次发布指令）

已知事实只有：男生想夹菜，女生正在拍菜，男生等着；没有拍摄次数、性别统计或真实用户经历。

**抖音**
标题：菜快凉了，手机还没吃饱
正文：我等的是开饭，她等的是光线。你们吃饭前，也有这道流程吗？
topics：生活日常、吃饭先拍照、情侣日常
封面意图：筷子停在半空，女生举手机拍菜；文字“手机先吃”。未有真实图URL时只写意图，不伪造地址。

**公众号原生视频**
标题：一顿饭，手机先吃
正文：菜端上桌，他刚拿起筷子，她举起了手机。\n\n一个想趁热吃，一个想留下最好看的样子。原来等一句“开饭”，也能发生一场小小的拉锯。
topics：不传；自定义封面：不传。这是视频描述，不凭此生成一篇长图文。

**小红书**
标题：吃饭前，先过手机这一关
正文：菜还冒着热气，筷子已经准备好了。\n她：等一下，我再找个角度。\n他：我吃饭，怎么还得给手机让座？\n\n如果你也有一位“手机先吃”的饭搭子，应该能懂这个等待。
如要话题，按实际工作流把少量#主题写入description；不要添加不存在的topics参数。

**X**
内部title：The phone eats first
text：He’s ready for dinner. She’s still finding the angle. The food is getting cold, but the phone hasn’t finished eating.
本例只展示配文；X目前不支持发这个视频，只能在明确授权下另选文字或已有支持图片。

## 准备、检查与交付

1. 取作品及目标账号方案，确认素材真实呈现的梗。视频无法查看时说明信息来源，不凭标题补剧情。
2. 按目标渠道改写，保留用户给定的事实与语气；标题、正文、topics、封面意图分开。
3. 将写作结果映射到[真实工具字段](publishing-parameters.md)。工具不支持的字段只保留为方案或明确省略，不能声称已应用。
4. 有保存方案授权时逐渠道保存；独立revision和requestId，保留其他渠道与历史记录。没有封面资源就使用实际可用默认，不伪造链接。
5. 发布/存草稿仅执行本次指定目标，不因为准备了九渠道文案就发九个平台；已有明确授权无需重复问同一个问题。
6. 结果按“渠道、账号、实际标题正文、标签/封面应用范围、草稿或发布状态、原请求号/回执”交付。正文只写主题相关内容；平台必需声明通过其实际能力处理。

检查重点：不是各渠道一模一样，也不是为了不同而乱改故事。不要每条都套“你有没有过…评论区告诉我”，不编热度、热门标签、效果数据或未发生的对话。用户要求热点检索时另用已有研究能力，写作建议本身不声称最新趋势。
