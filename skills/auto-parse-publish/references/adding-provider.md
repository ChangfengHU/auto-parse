# 增加发布工具

稳定插件ID为vyibc-auto-publish，统一入口Skill为auto-parse-publish。不为每个平台另建同名插件或复制服务实现。

现有平台新增流程/节点：先发现真实tools/schema与workflow_capabilities，读取正式工作流；增加一条targets.json索引与独立参考说明，记录支持媒体、输入、账号绑定、浏览器、准备/发布模式、回执与恢复边界。已有技能目录仅作路由提示，不能运行本地JSON替代Supabase。
新增自媒体平台：建立该平台专用端点、独立认证及允许的流程/工具，先完成部署、授权、只读握手及tools/list验证，登记固定MCP版本；Skill requires与同一插件components加入平台MCP固定引用，再发布新Skill版本和同一插件的更高版本。不能向旧固定版本悄悄加工具或伪称客户端已自动升级。

任何新增路线必须有：用户意图→账号/素材核对→准备→授权提交→真实回执→必要可见性回查；明确稳定意图ID、未知提交不重试、锁与并发模型。提供服务端状态或对账工具；没有的明确标注，不用AI猜测作品ID。
验证分层：协议/工具发现、结构校验、真实准备、授权实发、账号内回查、匿名可见性。只记录实际通过的层；插件封装不会把之前未验收的发布方式升级为已验收。不得为了发布插件而发公开占位测试帖。
保留已有路由、原工作流、历史固定包与发布账本。按Hub规范先预览后提交，稳定requestId并回读；出错先查原回执，不改ID绕过冲突。已安装客户端需正常更新/重连，不保证热加载。

不按后端服务或媒体类型拆分MCP。每个自媒体平台一个发布MCP，同平台视频、图文等由其能力和工具区分；X不需要拆成文字MCP和图片MCP。共享后端工作流/上传/去重执行器，服务端检查平台身份、允许的workflowId、浏览器及会话归属，不以卡片改名代替权限隔离。通用工作流编辑和跨平台研究能力不随本发布插件授权。
