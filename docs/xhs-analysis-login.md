# 小红书分析页登录与数据读取

入口：https://auto-parse-v2.vyibc.com/analysis/xhs。

## 复用已登录的84浏览器

在页面打开“登录设置”，选择已登录小红书的浏览器实例，点击“复用已登录浏览器”。同步只访问所选实例：持有活动锁、创建独立任务标签页、通过小红书原生user/me响应验证非游客身份，再把该域的会话保存到分析服务。不会重新登录、切换其他账号、重启浏览器或关闭用户标签页。
没有有效登录时明确报错，不因为存在Cookie或页面昵称就宣称成功。正在被其他任务占用时等待用户重试，不抢锁。两个实例可对应不同账号，用户必须选择预期实例；不会自动扫描其他机器或任选账号。

HTTP接口：POST /api/analysis/xhs/login/browser，输入browserInstance为1或2，confirmBrowserControl:true，可选本平台clientId。公开响应仅含同步状态及账号标识，不返回Cookie。服务授权与访问范围仍沿用现有所有者工作台，不宣称此改造构建了多租户账号隔离。

## 官方网页扫码

“一键扫码登录”使用服务端浏览器1打开小红书官方登录页，直接展示官方二维码图片。只有验证到原生user/me响应guest=false及完整会话后才同步登录。4分钟超时、主动取消、页面关闭或原生轮询失败都会停止；只关闭本任务标签页并断开CDP，释放活动锁。
GET /api/analysis/xhs/login/qr返回不透明loginId、图片及过期时间；POST /login/poll只接受该句柄，DELETE /login/qr取消会话。会话不跨服务重启保留，过期需重建。旧HTTP流程的a1/webid/Cookie参数不再由页面传递。生产响应与二维码均no-store。
图片在本站直接显示，不把二维码链接传给第三方二维码服务。客户端串行轮询，不重叠请求；取消后忽略晚到响应，终止状态不再定时重试。
安全验证必须由账号本人在官方页面/App中完成；Captcha required、code=-1不能靠密集重试或伪造字段消除。

## 会话与验收

分析会话存放原有.xhs-cookie（权限600），按已提供的xhs_凭证ID可同步到既有服务端会话表。只存会话，不记录账号密码。Cookie状态页面不再回显Cookie前缀；日志只记录独立trace及阶段，不记录会话值。浏览器登录与分析服务登录原本分离，需要上述导入或成功扫码才能连接。

2026-10-28实际验证：
- 同一机器，旧纯HTTP轮询返回code=-1或安全验证，而官方网页二维码轮询正常。
- 真实页面二维码加载成功，连续4次轮询HTTP200/waiting，不暴露Cookie，取消后资源释放。
- 用户自行登录浏览器2后，先验证真实非游客账号，再同步。分析登录校验返回valid=true，数据接口返回非空热门内容。
- 页面“复用已登录浏览器”按钮实测成功，实际渲染37篇热门笔记；正式服务重启后会话恢复有效，热门接口读到38条。不同时间结果数量为当次快照，不等同固定总量或平台完整数据。
- 11项专项回归、独立TypeScript、重点ESLint与生产构建通过。ESLint保留既有图片元素及无用禁用声明警告，无错误。未发布、点赞、评论或修改小红书内容。

现有分析读取仍使用既有后端；获得有效会话后，读取功能需单独验收。日后会话失效或平台再次要求验证，重新同步/正规登录，不能保证一次登录永久有效。API监控上报apm-fe.xiaohongshu.com/api/data中的用户标识不是登录凭据，不应拿它当Cookie导入。

## 回滚

保存的上一构建可在服务空闲并取得浏览器活动锁后切回，只重启AutoParse。保留现有会话文件和浏览器配置；回滚不代表撤销平台会话，也不要清除用户已登录浏览器。
